# XMarkdown v0.2.0 · The first public MVP

**Familiar Markdown. Richer documents. One shared renderer.**

XMarkdown brings charts, diagrams, mathematics, interactive controls, drawing, and complex SVG into the documents you already write. Describe the content and visual data; the renderer supplies the supported layout, geometry, and interactions.

[![XMarkdown — Markdown with more to say](https://xmarkdown-zeta.vercel.app/assets/social.svg)](https://xmarkdown-zeta.vercel.app)

**[Explore the live showcase ↗](https://xmarkdown-zeta.vercel.app)** · **[Read the syntax guide](https://github.com/muhammadhaseebiqbal-dev/XMarkdown/blob/v0.2.0/docs/extended-capabilities.md)** · **[Install and integrate](https://github.com/muhammadhaseebiqbal-dev/XMarkdown/blob/v0.2.0/docs/integrations.md)**

## ✨ What’s included

| Capability | What you can build |
| --- | --- |
| **Familiar Markdown** | Headings, paragraphs, emphasis, lists, blockquotes, links, code fences, tables, and strikethrough, plus note/tip/warning callouts. |
| **Declarative charts** | Bar and line charts with axes, labels, titles, and descriptions, generated from structured data. |
| **Directed diagrams** | Pipelines, branching dependencies, release gates, and rollback loops with automatic basic node placement. |
| **Mathematics** | Inline and display equations, aligned derivations, matrices, and piecewise notation, rendered as native MathML through KaTeX. |
| **Calculated controls** | Range, number, select, and toggle inputs connected to outputs through a bounded expression interpreter. |
| **Drawing** | An SVG drawing surface with undo and clear, powered by the shared widget runtime. |
| **Vector scenes** | Paths, groups, gradients, patterns, clipping, masks, markers, and reusable symbols in a compact scene format. |
| **SVG imports** | Existing SVG markup inside an `x-svg` fence, validated against the static import profile. |
| **Streaming previews** | Provisional section updates during generation, followed by a complete parse when the document finishes. |

## 🧩 One engine across Node, the browser, and React

This release includes a synchronous **Node API**, an asynchronous **browser API**, an exported **React component**, shared **CSS**, and **TypeScript declarations**.

The showcase uses the actual XMarkdown renderer: static examples are built with the Node entry, edited source is parsed locally in the browser, and the React demo mounts the exported component. Both parser entries share the same core, validators, geometry, and renderers. Optional math and XML processors load on demand; widget assets are required only for interactive documents.

| Package entry | Purpose |
| --- | --- |
| `xmarkdown` | Node parsing and streaming |
| `xmarkdown/browser` | Browser parsing with lazy processor preparation |
| `xmarkdown/react` | `<XMarkdown source={source} />` or a parsed document |
| `xmarkdown/widgets` | Mount supported controls and drawing |
| `xmarkdown/frame` | Wrap a document for an isolated preview |
| `xmarkdown/styles.css` | Shared renderer styles |

The integration guide also includes **Next.js, Vue, and Svelte recipes**, plus a **bounded HTTP bridge** for Python, Go, and other server languages. Full framework applications beyond the tested React integration remain future verification work; the bridge uses the JavaScript implementation.

## 🌱 MVP profile and what comes next

Version 0.2.0 is an early public MVP, and APIs/schemas may change before 1.0. The Markdown core uses **markdown-it**, TeX processing uses **KaTeX**, and SVG import tokenization uses **saxes**. XMarkdown adds the document profile, extension schemas, validators, graphics rendering, widgets, caching, and streaming coordination.

The renderer accepts a **bounded document profile**: author HTML is escaped, images display alt text, and SVG imports support static local content. Scripts, external SVG assets, filters, and animation fall outside that profile. See the [security policy](https://github.com/muhammadhaseebiqbal-dev/XMarkdown/blob/v0.2.0/SECURITY.md) for integration limits.

Next priorities are conformance and fuzzing, improved graph routing and accessibility, a cancellable worker distribution, broader framework verification, npm publication, and capability-matched AI/reader evaluations.
